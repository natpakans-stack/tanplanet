# น้องกริ่ง — แผงคุม (ring-bot)

Apps Script เดิมของบอทสวัสดีตอนเช้า ต่อยอดเป็นแผงคุม:
**สร้างบิล → เตือนตามวัน-เวลาที่ตั้ง (ทำซ้ำได้)** + ดูเครดิต/สถิติการส่ง

| ไฟล์ | ทำอะไร |
|---|---|
| `Ring.js` | ของใหม่ทั้งหมด — ฟอร์ม, webhook, การ์ด Flex, เครื่องยิงบิล, สิทธิ์เมนู |
| `bill.html` | หน้าฟอร์มสร้างบิล (เสิร์ฟจาก `doGet`) |
| `banklogos.html` | โลโก้ธนาคาร 14 แห่ง ฝังเป็น data URI |
| `qrlib.html` | qrcode-generator (MIT) สำหรับวาด QR พร้อมเพย์ |
| `Code.js` `LineApi.js` `ImageGen.js` `DayData.js` | ของเดิม (บอทรูปสวัสดี จบภารกิจ 29 พ.ค. 69) |
| `richmenu/menu.html` → `menu.png` | ภาพ Rich Menu 2500×1686 |
| `richmenu/setup.sh` | สร้าง + อัปโหลด rich menu (ไม่ตั้ง default) |

> **repo นี้เป็น public** — URL ของ web app คือความลับในตัว (ใครมีก็เปิดฟอร์มสร้างบิลได้)
> ค่าจริงทั้งหมดอยู่ใน `.env` ซึ่ง gitignored ไว้ · ดู deployment ปัจจุบันด้วย `npx @google/clasp list-deployments`

## ใครใช้เมนูได้บ้าง

**ไม่มี default rich menu** — คนที่แอดน้องกริ่งเฉย ๆ จะไม่เห็นเมนู ไม่มีทางเปิดฟอร์ม

เพิ่มคน:
1. คนนั้นทัก 1:1 น้องกริ่งหนึ่งครั้ง → ชื่อโผล่แท็บ `targets`
2. ในชีต ช่อง **`ให้ใช้เมนู`** พิมพ์ `ใช่`
3. Apps Script → Run **`ringSyncMenu`** → เมนูไปโผล่เฉพาะคนที่ติ๊ก (ลบ `ใช่` แล้วรันซ้ำ = ถอนสิทธิ์)

> ดึงรายชื่อสมาชิกกลุ่มอัตโนมัติไม่ได้ — `/group/{id}/members/ids` เปิดให้เฉพาะ OA verified/premium
> (เช็กแล้ว: `/followers/ids` ตอบ 403) เลยใช้ allowlist ในชีตแทน

## ตั้งครั้งแรก

1. Apps Script → เลือกไฟล์ `Ring.gs` → Run **`ringSetup`** (อนุญาตสิทธิ์ครั้งแรก)
   สร้างแท็บ `bills`/`pushlog`/`targets` + ตั้ง trigger `ringTick` ทุก 5 นาที
2. LINE Developers → Messaging API → Webhook URL = `$WEBAPP_URL` → เปิด *Use webhook*
   (ปุ่ม Verify จะขึ้นแดง 302 เสมอ — ปกติของ Apps Script ไม่ใช่พัง)
3. LINE OA Manager → Response settings → Response method = **Manual chat** (ปิด auto-response)
4. ทัก 1:1 → ติ๊ก `ให้ใช้เมนู` = `ใช่` → Run **`ringSyncMenu`**
5. ติดตั้งเมนู (ทำแล้ว รันซ้ำเมื่อแก้ภาพ/ปุ่ม):
   ```bash
   cp .env.example .env      # ใส่ CHANNEL_ACCESS_TOKEN
   ./richmenu/setup.sh
   ```

## ชีต `bills`

`id` `สร้างเมื่อ` `โหมด` `ปลายทาง` `ชื่อบิล` `คู่กรณี` `ยอด` `ธนาคาร` `ชื่อบัญชี` `เลขบัญชี`
`เริ่มเมื่อ` `เตือนเมื่อ` `ทำซ้ำ` `จำนวนครั้ง` `ส่งไปแล้ว` `สถานะ` `ส่งล่าสุด` `โน้ต`

- **โหมด** — `ทวง` (เราเก็บเงิน) / `จ่าย` (เราต้องจ่าย) — เปลี่ยนหัวการ์ดกับสี
- **ทำซ้ำ** — ว่าง / `เดือน` / `สัปดาห์`
- **จำนวนครั้ง** — ว่าง = ไม่มีจุดสิ้นสุด
- **เริ่มเมื่อ** — วันหลักที่ใช้คำนวณทุกรอบ (แก้ตรงนี้ = เลื่อนทั้งชุด ไม่ drift)
- **สถานะ** — ว่าง = รออยู่ · `จบแล้ว` = ครบรอบ · `ปิดแล้ว` = กดปิดจากการ์ด
- เดือนที่ไม่มีวันที่ 29/30/31 → เลื่อนเป็นวันสิ้นเดือน แล้วเดือนถัดไปกลับวันเดิม

## พร้อมเพย์ / QR

- ฟอร์มโหมด "พร้อมเพย์" → ใส่เบอร์/เลขบัตรครบหลัก → QR ขึ้นสด
- payload สร้างฝั่ง server (`ppPayload` ใน `Ring.js`) ที่เดียว — ฝั่งหน้าเว็บแค่วาด
- ใส่ยอด = ยอดล็อกมากับ QR (POI `12`) · เว้นว่าง = ผู้จ่ายกรอกเอง (POI `11`)
- QR ที่สร้างถูกเก็บใน Drive โฟลเดอร์ `น้องกริ่ง QR` แชร์แบบ anyone-with-link เพื่อให้ LINE โหลดรูปได้
- `ringSelfTest` คุม CRC-16/CCITT (ค่า check `"123456789" → 0x29B1`) + โครง payload

## เชื่อม Budget-Bajjo → ส่งยอดให้โจ้

`ringTick` อ่านเฉพาะยอดแถว **แม่** และ **แทน** ใต้หัวสรุป **รายการโอน / ยอดที่โอน**
ไม่อ้างอิงยอด `อื่นๆ` หรือยอดรวม จากนั้นสร้าง QR แยก 2 ใบด้วย PromptPay และยอดของแต่ละคน
แล้วเพิ่มเป็นบิลปกติ 2 records ในแท็บ `bills` ก่อนเสมอ (`แม่` และ `แทน`) โดยไม่ส่ง LINE ลัดหลังบ้าน
`ringTick` รอบถัดไปจึงส่งผ่าน pipeline เดิมและบันทึกสถานะ/เวลาส่ง/`pushlog` ครบ ทำซ้ำทุกเดือน
และมี idempotency key รายเดือนกัน import ซ้ำ

แท็บ `budgetlog` ใน Google Sheet ของแผงควบคุมเก็บผลเป็นตารางว่า `ยังไม่สร้างบิล`, `สร้างบิลแล้ว`,
`ส่งสำเร็จ` หรือ `ส่งไม่สำเร็จ` พร้อมเดือน รายการยอด และรายละเอียดปัญหา โดย error ข้อความเดิมจะบันทึก
เพียงครั้งเดียวจนกว่าสถานะหรือสาเหตุจะเปลี่ยน

ก่อนสร้างบิล ระบบมี safety gate ตรวจว่าแถว `ค่าไฟ***` มีสูตรส่วนแบ่ง `*0.6`, มียอดมากกว่าศูนย์,
มี Note ยืนยันจาก MEA e-Invoice และ `รอบบิล` ใน Note เป็นเดือนก่อนหน้าแท็บเป้าหมาย หากยังไม่พร้อม
จะไม่สร้าง record หรือ QR และ `ringTick` จะลองใหม่ทุก 5 นาทีจนกว่าข้อมูลจะครบ

ตั้ง Script Properties เหล่านี้ในโปรเจกต์ `ring-bot`:

| Property | ค่า |
|---|---|
| `BUDGET_SEND_DAY` | ไม่บังคับ; default คือวันที่ `28` ของทุกเดือน |
| `BUDGET_SEND_TIME` | ไม่บังคับ; default คือ `09:00` น. ตามเวลา Asia/Bangkok |
| `BUDGET_LINE_USER_ID` | ไม่บังคับ; ระบบใช้ปลายทางของบิลแม่/แทนล่าสุดเป็น LINE ของโจ้ หรือใส่ค่านี้เพื่อ override |
| `BUDGET_MOTHER_PROMPTPAY` | ไม่บังคับ; fallback เมื่อยังไม่มีบิลที่ตั้งคู่กรณี=`แม่` และธนาคาร=`พร้อมเพย์` ในแผงควบคุม |
| `BUDGET_TAN_PROMPTPAY` | ไม่บังคับ; fallback เมื่อยังไม่มีบิลที่ตั้งคู่กรณี=`แทน` และธนาคาร=`พร้อมเพย์` ในแผงควบคุม |
| `BUDGET_SHEET_ID` | ไม่บังคับ; ค่า default คือชีต `คำนวณค่าใช้จ่ายโจ้` |

ก่อนเปิดใช้งาน ให้รัน `previewBudgetPayment` เพื่อดู log ว่าอ่านแท็บ/หมวด/ยอดถูกต้อง แล้วรัน
`ringSetup` หากยังไม่มี trigger `ringTick` ทุก 5 นาที ความแม่นเวลาจึงอยู่ที่ประมาณ ±5 นาที

QR ฝั่ง scheduled job สร้างผ่าน goQR API แล้วเก็บ PNG ในโฟลเดอร์ Drive `น้องกริ่ง QR`;
PromptPay payload (เลขผู้รับและยอด) จึงถูกส่งไปยังบริการดังกล่าวตอนสร้างรูป

## สลากกินแบ่งรัฐบาล

ส่งผลรางวัลเข้ากลุ่ม **sirirat.fc** อัตโนมัติทุกงวด + ตรวจเลขให้ในแชท

**ยิงผลงวดใหม่** — เกาะ `ringTick` ตัวเดิม ไม่มี trigger เพิ่ม
เปิดหน้าต่างเช็ค 15:00–20:00 แล้ว poll เอา (ไม่ต้องรู้ปฏิทินงวด งวด 1/16 เลื่อนตามวันหยุดได้)
เจองวดที่ยังไม่เคยส่ง → ส่งการ์ดเข้ากลุ่ม แล้วจำไว้ใน `LOTTO_LAST_SENT` ส่งซ้ำไม่ได้
งวดเก่ากว่า 3 วัน = ข้าม (กันตอนรันครั้งแรก/เพิ่งกู้ระบบแล้วเด้งผลเก่าเข้ากลุ่ม)

**ตรวจเลขในแชท** — พิมพ์ได้ทั้งใน 1:1 และในกลุ่ม
- `458145` หรือ `458145, 123456` (คั่นด้วย `,` หรือเว้นวรรค ได้ถึง 30 ใบ) → การ์ดผลตรวจ
- `หวย` / `ตรวจหวย` / `สลาก` / `ผลสลาก` → การ์ดผลงวดล่าสุด
- ต้องเป็นเลข 6 หลักล้วนเท่านั้นถึงจะตอบ — `โอน 123456 บาท` ไม่ทริกเกอร์ บอทเลยไม่ป่วนกลุ่ม
- **ไม่คำนวณเอง** ส่งเลขให้ระบบ GLO ตัดสิน จึงครบตั้งแต่รางวัลที่ 1–5 ข้างเคียงรางวัลที่ 1
  เลขหน้า/เลขท้าย 3 ตัว และเลขท้าย 2 ตัว · เงินรางวัลอ่านจากผลเต็มของงวดนั้น ไม่ฮาร์ดโค้ด
- ปุ่มท้ายการ์ดลิงก์ไป PDF ใบตรวจทางการของงวดนั้น

**ปลายทาง** — หาจากแท็บ `targets` เอง: แถวที่ `ชนิด=group` และชื่อมีคำว่า `sirirat.fc`
กลุ่มต้องเคยพิมพ์ให้บอทเห็นสักครั้งชื่อถึงจะโผล่ · ทับด้วย Script Property `LOTTO_LINE_TARGET` ได้

**API ของ GLO** (เปิดสาธารณะ ไม่ต้องใช้คีย์ · เอกสาร: gdcatalog.glo.or.th `dataset_c4-9_01`)

| endpoint | body | ได้อะไร |
|---|---|---|
| `lottery/getLotteryResultByPage` | `{page:1,limit:1}` | งวดล่าสุด**ที่ประกาศแล้ว** + เลขสำหรับการ์ด |
| `checking/getLotteryResult` | `{date,month,year}` | ผลเต็มทุกรางวัล + เงินรางวัล + `pdf_url` |
| `checking/getcheckLotteryResult` | `{number:[{lottery_num}],period_date}` | ให้ GLO ตรวจให้ ครั้งละ 10 ใบ |

> **กับดัก:** `getLotteryResultByPage` ถ้าไม่ส่ง `page` จะคืน `response: null` เงียบ ๆ ไม่ใช่ error
> เช่นเดียวกับ `getPeriodsByYear` ที่ต้องมี `type` (`CHECKED` / `BLOCKED`)
> `getLatestLottery` คืน "งวดถัดไป" ไม่ใช่งวดที่ประกาศผลแล้ว — อย่าเอามาใช้หาเลข

API สาธารณะเจ้าอื่นที่คนชอบแนะนำ (`lotto.api.rayriffy.com`, `api.chnwt.dev`) ตายหมดแล้ว

**เทสต์**
- `ringSelfTest()` — offline: การแยกเลข, งวดไทย, ความครบของตาราง `LOTTO_TIER`
- `lottoSelfTestLive()` — ยิง GLO จริงด้วยงวด 16 ส.ค. 69 เช็คว่ายังตรวจครบทุกชั้น (รางวัลที่ 1–4, ข้างเคียง, เลขหน้า/ท้าย, ใบที่ไม่ถูก) รันเวลาสงสัยว่า API เปลี่ยน
- `lottoNow()` — ดูว่าเจอกลุ่มไหม แล้วยิงการ์ดงวดล่าสุดเข้ากลุ่มเลย

## ที่ต้องรู้

- โควตาฟรี 300 ข้อความ/เดือน — **push กินโควตา, reply ไม่กิน** ปุ่มในเมนูใช้ reply ทั้งหมด
- บิลทำซ้ำ "ไม่มีจุดสิ้นสุด" = 1 ข้อความ/รอบ ตลอดไป — ดูโควตาก่อนตั้ง
- `ringTick` เขียนสถานะลงชีต **ก่อน** push → push พังก็ไม่ยิงซ้ำ (แลกกับพลาดรอบนั้นไป)
- `ringSelfTest` — เช็ก logic เงิน/วันที่/รอบทำซ้ำ รันก่อนแก้อะไรที่แตะเลข
- ความแม่นเวลา ±5 นาที (คาบ trigger) ปรับที่ `ringSetup`
