Background

Every time I wanted to tell Claude "fix this element", I had to gather the details by hand

As a UX designer who uses Claude as a design assistant, I hit the same problem every day: to say "please fix this element", I had to open DevTools → find the details → copy the CSS → format it → paste it into the prompt every single time

That took 2–3 minutes per element and happened dozens of times a day. It added up to far more time than I expected.

Features

Point · click · get Markdown ready to paste

Four core features that get element details to Claude in one click

  • Hover Inspect Point at an element to see a colored box-model overlay (margin/padding/content) with a tooltip showing tag, size and font
  • Detail Panel Click an element to open a right-hand panel with a box-model diagram, computed styles, an HTML snippet and CSS variables
  • Auto Copy Markdown Click or press ⌘+C to copy the element's details to the clipboard as Markdown, ready to paste into a Claude prompt
  • Visual Feedback A blue flash highlight + a floating toast pill at the bottom confirm whether the copy worked

Design Decisions

What I decided, and why

Five key decisions that keep the extension working on any site without breaking

DecisionChoiceWhy
UI IsolationShadow DOMPrevents style clashes with the inspected site. Whatever CSS the site uses, nothing breaks.
Panel ThemeDark (#1e1e2e)Less visual conflict with the site, and it looks like the dev tools designers already know
ClipboardOffscreen DocumentThe content script has no clipboard permission → send through background → an offscreen document with a full DOM
Output FormatCompact MarkdownClaude reads structured text better than images: fewer tokens, easier to edit
Drop screenshotsText-onlyTesting showed the image clipboard is unreliable across browsers. Text works 100% of the time.
Iteration Journey

Five rounds of refinement, from usable to good

Each round came from real use. Some added things, some cut them.

01

v1.0 — Hover + Panel + Manual Copy

Could inspect elements, but copying still needed a button press → slower than it should be

02

v1.0 + Screenshot: removed

Added auto-screenshot + element highlight capture → the image clipboard was unreliable, slowed the flow and made file downloads messy → removed

03

Clipboard Fix — Offscreen Document

navigator.clipboard did not work in the content script because the user gesture expires after an async call → fixed by sending the copy to an offscreen document via background

04

Shorter Markdown: from verbose to compact

The original Markdown had a table + ASCII box model, about 400 tokens → condensed to one-line styles, about 200 tokens, saving 50% of context

05

v1.1 — Cleanup & Ship

Removed 224 lines of dead code (screenshot.js, styles.css), made error handling consistent, cut the file count from 7 to 5

Learnings

What I learned

Four lessons from building a tool for myself

Clipboard ≠ Simple: Content scripts have no direct clipboard permission. You need to understand the user gesture lifecycle and use an offscreen document as a proxy.

Less > More: The screenshot feature looked good on paper but was slow and unreliable in practice. The tool is better without it.

Shadow DOM Isolation: If you inject UI into a page, use Shadow DOM. Otherwise the site's CSS and the extension's CSS will clash, guaranteed.

Design for AI Context: Output for AI has to respect a token budget. More data is not better; it needs to be compact and structured.
