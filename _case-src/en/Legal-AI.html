Legal AI
Thai legal research with AI

A research tool for lawyers covering 84,000+ sections of Thai law. Ask in plain language and get an answer that cites real sections from the database.

Overview

Legal AI is a proof of concept for Thai legal research. It uses RAG (Retrieval-Augmented Generation) to pull the actual text of each section from a database and give it to the AI as context. Answers are not generated from general knowledge; they cite real laws scraped from the Office of the Council of State (OCS).

Design Thinking Process

Why lawyers need a tool like this

01

Empathize · Lawyers and legal research: the hidden problem

To prepare a single case, a Thai lawyer may need to search 84,000+ sections across many acts. The usual way is keyword search on the OCS website, which only works if you know the exact name of the act or the section number. If you don't, you won't find it.

Insight: lawyers know the "situation" but not which "section" to look up. They need a tool they can ask in plain language.

02

Define · "If the AI gets the law wrong, you could lose the case"

ChatGPT can answer legal questions, but it often cites the wrong section or hallucinates laws that don't exist, which is dangerous in legal work. The system has to cite real law that can be checked.

HMW: How might we build an AI that answers legal questions accurately, citing only real sections from the database?

03

Ideate · RAG: make the AI cite from a real database

Use RAG (Retrieval-Augmented Generation) instead of letting the AI answer from general knowledge:

• Scrape 1,811 laws and 84,376 sections from OCS
• Full-text search + vector search (pgvector) to find relevant sections
• Send the actual section text to GPT-4o as context
• Instruct the AI to cite only sections that appear in that context

04

Prototype · 3-Panel Layout — Chat + Citations + Law Viewer

The chat page has 3 parts: a sidebar (chat history), the chat area (AI answers with Citation Cards) and a Law Viewer panel (the actual legal text). Tapping a Citation Card opens the real text right away without leaving the chat.

Key decision: Citation Cards use 3 colors (green/purple/blue) by the role of each law, so lawyers can grasp the overall picture quickly.

05

Test · Comparison Testing — Legal AI vs Gemini Pro

I used Playwright to run 5 legal questions through Legal AI and Gemini Pro side by side:

• Legal AI: better structured output (citations + summary), with the cited sections clearly visible
• Gemini: more detailed and more complete content
• Next: add vector search to retrieve relevant sections more precisely

OCS Scraper

Legal data pulled from the Office of the Council of State

scripts/scrape-sections.ts
// Scrape 84,376 sections from OCS API
for (const law of laws) {
  const doc = await fetch(`OCS_API/getLawDoc?id=${law.id}`);
  const sections = parseSections(doc);
  await supabase.from('law_sections')
    .upsert(sections, { onConflict: 'law_id,section_number' });
}
// Result: 1,811 laws, 84,376 sections (deduplicated)

Lessons Learned

What I learned building Legal AI

RAG beats fine-tuning for domain-specific data. Fine-tuning a model is expensive and hard to maintain. Scraping the real data into a database and using RAG so the AI cites it gives results that are far easier to verify.

Prompt engineering matters a lot. From v1, where the AI hallucinated sections, to v13, which says "ONLY cite sections that APPEAR in the context", hallucination dropped significantly.

Hybrid search (FTS + vector) beats FTS alone. Full-text search only finds keyword matches, while vector search picks up meaning. For example, a question about "dismissal" also finds sections on "severance pay".

Structured output helps UX a lot. Having the AI return JSON (content + citations + summary) instead of plain text makes it possible to build an orderly, interactive UI (tap a citation to read the real law).

Color-coded citations reduce cognitive load. Three colors (green/purple/blue) by the role of each law let lawyers see the big picture without reading every line.
